# API Contract

The exact JSON shapes between the hub, the app and the cloud. Written 2026-10-18 at the start of the build. The hub, the app and the cloud code against this file. A change here is a change in all three, in one pull request.

Conventions for every route below:

- JSON bodies, UTF-8. Timestamps are ISO 8601 strings with an offset, for example `2026-10-18T17:42:11+05:30`. Dates are `YYYY-MM-DD`.
- Ids are ULIDs (26 characters, Crockford base32), generated by the side that authors the row. Ids are prefixed by kind for readability: `m_` member, `c_` consent record, `s_` staff, `h_` household, `p_` purchase, `v_` visit, `k_` clip, `e_` outbox event. Example: `m_01JAB3C4D5E6F7G8H9J0K1M2N3`.
- Money is `amount` in rupees as a number with at most two decimals.
- Errors are `{"error": "<code>", "detail": "<human text>"}` with the HTTP status. Codes used: `unauthorized`, `forbidden`, `not_found`, `invalid`, `under_18`, `no_face`, `conflict`, `rate_limited`, `locked`, `payload_forbidden`.
- Phone numbers travel as E.164 (`+919876543210`). The hub normalises 10-digit Indian mobiles and `+91` or `91` prefixes.

## 1. Hub LAN API (app to hub)

Base URL `https://<hub-address>:8443`. Self-signed certificate; the app pins the SHA-256 fingerprint returned by `POST /pair`. Every route except `GET /health` and `POST /pair` needs `Authorization: Bearer <app_token>`.

### GET /health

```json
{"ok": true, "version": "0.1.0", "model_version": "buffalo_l:3f9a1c2d", "uptime_s": 3600,
 "gallery_size": 42, "locked": false, "data_dir_encrypted": false, "internet": true,
 "outbox_pending": 0, "outbox_failed": 0, "clock_synced": true, "fps": 6.8, "stream": "ok"}
```

`stream` is `ok`, `connecting` or `down`. `locked` is true while the data directory waits for the cloud unlock token.

### POST /pair

Request `{"code": "K7QM-2XPA"}`. The code is either the hub pairing code (gives role `owner`, one use) or an invite code from `POST /pair/invite` (gives role `counter`, one use, 10 minutes).
Response `{"app_token": "<opaque>", "cert_sha256": "AB:CD:...", "shop_id": "sharma-jewellers-jaipur", "role": "owner"}`.
Wrong codes: 401. More than 5 wrong tries per minute from one address: 429.

### POST /pair/invite (owner token)

Response `{"invite_code": "483920", "expires_at": "..."}`.

### Staff

- `POST /staff` (owner token) `{"name": "Ravi", "role": "cashier", "pin": "4821"}` returns 201 `{"staff_id": "s_..."}`. PIN is 4 to 6 digits.
- `GET /staff` returns `[{"id": "s_...", "name": "Ravi", "role": "cashier", "created_at": "..."}]`.
- `POST /staff/verify-pin` `{"pin": "4821"}` returns `{"staff_id": "s_...", "name": "Ravi", "role": "cashier"}` or 401.

### POST /enrol

```json
{
  "staff_id": "s_...",
  "phone": "9876543210",
  "display_name": "Rajesh Sharma",
  "bill_no": "INV-2026-10-18-0417",
  "amount": 20000,
  "items": "Gold necklace",
  "occasion": "Daughter's engagement",
  "notes": "Asked about matching earrings",
  "household_label": "Sharma family",
  "payer_index": 0,
  "faces": [
    {"crop_jpeg_b64": "<base64 JPEG, under 300 KB>", "landmarks": [[x, y], [x, y], [x, y], [x, y], [x, y]],
     "display_name": "Rajesh Sharma", "phone": null}
  ]
}
```

- `faces` may be empty: that records a phone member (purchase only, no template, no consent record, never matched).
- Each face may carry its own `display_name` and `phone`; missing values fall back to the top-level ones. Each face member gets its own consent record and its own WhatsApp notice, and activates on that notice's delivery.
- `household_label` and `payer_index` are used only when two or more faces are accepted.
- Landmarks are in crop pixel coordinates in the order left eye, right eye, nose, left mouth corner, right mouth corner. The hub re-detects on the crop and uses these only as a fallback.

Response 201:

```json
{"phone_member": false, "household_id": "h_...",
 "members": [{"face_index": 0, "member_id": "m_...", "status": "pending_notice", "consent_record_id": "c_..."}],
 "refused": [{"face_index": 1, "reason": "under_18"}]}
```

- Every face refused: 422 `{"error": "under_18" | "no_face", "refused": [...]}`.
- The phone already belongs to a member who has a template: 409 `{"error": "conflict", "member_id": "m_..."}`.
- A phone that belongs to a phone member (no template) upgrades that member: same member id, template, consent record and purchase added.

### Members

- `GET /members?q=&phone=&status=` returns `[MemberSummary]` where `MemberSummary` is `{"id", "display_name", "status", "member_since", "last_seen_at", "household_label", "has_template", "phone_masked"}`. `phone_masked` is `+91******3210`.
- `GET /members/{id}` returns `MemberCard`: `MemberSummary` plus `{"phone": "+919876543210", "notes", "discount_flag", "household": {"id", "label", "payer_member_id", "member_ids"} | null, "purchases": [Purchase], "visits_count"}`.
- `Purchase` is `{"id", "bill_no", "amount", "items", "occasion", "ts"}`.
- `PATCH /members/{id}` `{"display_name"?, "notes"?}`; any other key is 400.
- `POST /members/{id}/remove` `{"staff_id": "s_..."}` returns `{"status": "withdrawn", "template_deleted_at": "..."}`.
- `POST /members/{id}/purchases` `{"staff_id", "bill_no", "amount", "items", "occasion"}` returns 201 `Purchase`.

### Households

- `POST /households` `{"label", "member_ids": [...], "payer_member_id"}` returns 201 `{"id": "h_..."}`.
- `PATCH /households/{id}` `{"label"?, "payer_member_id"?, "add_member_ids"?, "remove_member_ids"?}`. A member belongs to at most one household: 409 otherwise.

### Visits and clips

- `GET /visits?member_id=` returns `[{"id", "member_id", "ts", "camera", "score", "frames_agreed", "greeted", "greeted_by", "not_them", "has_clip"}]`, newest first.
- `PATCH /visits/{id}` `{"greeted"?, "greeted_by"?, "not_them"?}`.
- `GET /clips/{id}` streams `video/mp4`, LAN only.

### GET /consent/export

Returns `text/csv` with the columns of section 3, in chain order.

### WebSocket GET /ws

The first client message is `{"token": "<app_token>", "since": "<event id or null>"}`. The hub replies `{"type": "hello", "id": null, "ts": "...", "payload": {"shop_id": "..."}}` and replays events after `since` from the last 24 hours. Server messages are `{"type", "id", "ts", "payload"}`; the hub pings every 20 seconds with `{"type": "ping"}`.

- `alert` payload: `{"visit_id", "member_id", "display_name", "household_label", "last_visit", "last_purchase": {"amount", "items"} | null, "notes", "score", "frames_agreed"}`. `last_visit` is the visit before this one, or `member_since` when this is the first.
- `member_updated` payload: `MemberSummary`.
- `visit_feedback` payload: `{"visit_id", "greeted", "greeted_by", "not_them"}`.
- `health` payload: the `GET /health` body.

## 2. Hub to cloud sync

Base URL `REMU_CLOUD_URL`. The hub calls the cloud; the cloud never calls the hub. `Authorization: Bearer <device_token>` on every route except `POST /api/devices/claim`.

### POST /api/devices/claim

Request `{"pairing_code": "K7QM-2XPA", "serial": "<hub serial>"}`. Response 202 `{"status": "pending"}` until an owner pairs the code, then 200 `{"status": "paired", "device_token": "<opaque>", "device_id": "d_...", "shop_id": "..."}` exactly once.

### POST /api/devices/unlock

Response `{"unlock_token": "<base64url 32 bytes>"}`, or 403 when the device is unpaired or revoked.

### POST /api/hub/events

Request `{"events": [{"id": "e_...", "type": "...", "created_at": "...", "payload": {...}}]}`, up to 200 events in id order.
Response `{"results": [{"id": "e_...", "status": "acked" | "rejected", "reason"?: "..."}]}`. A 5xx or network error means retry the whole batch.

Event payloads:

- `consent_record`: the consent record of section 3, every column.
- `member_upsert`: `{"id", "shop_id", "household_id", "display_name", "phone_hash", "status", "member_since", "last_seen_at", "discount_flag", "notes", "has_template", "created_at", "updated_at"}`. `phone_enc` never leaves the hub.
- `household_upsert`: `{"id", "shop_id", "label", "payer_member_id", "member_ids", "created_at"}`.
- `staff_upsert`: `{"id", "shop_id", "name", "role", "created_at"}`. `pin_hash` never leaves the hub.
- `purchase`: `{"id", "member_id", "bill_no", "amount", "items_text", "occasion", "ts"}`.
- `notice_request`: `{"member_id", "consent_record_id", "phone_e164", "first_name", "shop_name", "language": "en" | "hi", "date"}`. The only event that carries a plain phone number.
- `visit_summary`: `{"id", "member_id", "ts", "camera", "score", "frames_agreed", "greeted", "greeted_by", "not_them"}`.
- `visit_feedback`: `{"visit_id", "greeted", "greeted_by", "not_them"}`.
- `alert`: `{"visit_id", "member_id", "ts"}`.
- `health`: the `GET /health` body.

The cloud rejects with 400 `payload_forbidden` any event whose payload has a key containing `vec`, `template`, `image`, `crop`, `clip`, `jpeg` or `embedding` (except the boolean `has_template`), or any string over 1,024 characters that decodes as base64.

### GET /api/hub/inbox?after=<cursor>

Response `{"messages": [{"id": "<cursor>", "type": "...", "payload": {...}}], "cursor": "<last id>"}`. Cursors are increasing integers as strings. Passing `after=n` acknowledges every message up to `n`.

Message payloads:

- `member_status`: `{"member_id", "status": "active" | "withdrawn", "reason": "notice_delivered" | "stop" | "owner_remove", "at"}`.
- `notice_status`: `{"member_id", "consent_record_id", "wamid", "whatsapp_status": "sent" | "delivered" | "read" | "failed", "status_ts", "delivered_at"}`.
- `thumbs_up`: `{"member_id", "at"}`.
- `visit_feedback`: `{"visit_id", "greeted", "greeted_by", "not_them"}`.
- `config`: `{"shop_name", "notice_language": "en" | "hi", "script_version", "notice_version"}`.
- `device_revoked`: `{}`.

### POST /api/hub/anchor

Request `{"date": "2026-10-18", "chain_head_hash": "sha256:..."}`. Response `{"ok": true, "match": true}`.

## 3. Consent record and hash chain

Columns, in this order for CSV export: `id, shop_id, member_id, bill_no, ts, cashier_id, channel, script_version, notice_version, purposes_json, notice_delivery_json, adult_check, withdrawn_at, template_deleted_at, prev_hash, record_hash`.

- `purposes_json` is an object `{"recognise_at_entry": true, "whatsapp_offers": true}`.
- `notice_delivery_json` is an object `{"printed_on_bill": false, "whatsapp_msg_id": null, "whatsapp_status": null, "delivered_at": null, "thumbs_up_at": null}`.
- `channel` is `verbal_at_counter` for enrolment, `whatsapp_webhook` for delivery and thumbs-up records, `owner_remove`, `whatsapp_stop`, `nightly_expiry` or `sweep` for deletion records.
- `prev_hash` is the previous record's `record_hash` for the shop, or `sha256:genesis` for the first.
- `record_hash` is `"sha256:" + hex(sha256(canonical(record without record_hash)))`.
- `canonical` is JSON with keys sorted at every level, no whitespace (`,` and `:` separators), non-ASCII characters kept as UTF-8 (not escaped), booleans and null as JSON literals. No record field is a float. Python: `json.dumps(obj, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`. TypeScript: a recursive key sort, then `JSON.stringify`.

## 4. Cloud routes used by the app (Owner mode)

Supabase Auth session in `Authorization: Bearer <supabase access token>`.

- `POST /api/shops` `{"name", "city", "notice_language"}` returns 201 `{"id"}`.
- `GET /api/shops/{id}/devices` returns `[{"id", "hub_version", "last_seen_at", "online", "locked", "chain_break"}]`.
- `POST /api/devices/pair` `{"shop_id", "pairing_code"}` returns `{"device_id"}`.
- `POST /api/devices/fcm-token` `{"shop_id", "fcm_token"}` returns 204.
- `GET /api/visits/{id}/card` returns the `alert` payload of section 1.
- `POST /api/visits/{id}/feedback` `{"greeted"?, "greeted_by"?, "not_them"?}` returns 204.
- `POST /api/members/{id}/withdraw` returns 202.
- `POST /api/shops/{id}/consent-export?format=csv|pdf` returns the file with header `X-Remu-Signature: <base64 Ed25519 signature>`.

FCM data message: `{"shop_id", "visit_id", "member_id"}` and nothing else.

## 5. Ops routes (Remu team)

`X-Remu-Ops-Key: <OPS_API_KEY>` header.

- `POST /api/ops/devices` `{"pairing_code", "serial"}` registers a provisioned hub, returns 201 `{"device_id"}`.
- `GET /api/ops/hubs` returns every device with status.
- `GET /api/ops/metrics?from=&to=` returns pilot metrics as JSON, or CSV with `Accept: text/csv`.
